# Лабораторна робота №2 — Варіант 10

**Тема:** Розробка консольних утиліт для задач кібербезпеки
**Варіант:** 10 — «Монітор термінів дії SSL/TLS сертифікатів»

## Встановлення залежностей

З кореня репозиторію, в активованому віртуальному середовищі з ЛР №1:

```bash
pip install -r requirements.txt
```

Переконайтесь, що `ruff` присутній у `requirements.txt`.

## Структура файлів

```text
labs/lab02/
├── __init__.py
├── main.py               # команди demo та analyze
├── task1.py               # класи User, Admin, Session, AuditLog, UserAccount
├── task2.py                # утиліта монітора SSL/TLS сертифікатів
├── README.md
└── data/
    └── data_v10/
        └── certificates.json   # тестові дані варіанта 10 (з lab2_data.zip)
```

## Вхідні файли

Утиліта `task2.py` приймає один JSON-файл із масивом об'єктів сертифікатів.
Кожен об'єкт має поля: `domain`, `issuer`, `validFrom`, `validTo`, `keyLength`,
`signatureAlgorithm`. Тестові дані знаходяться в `data/data_v10/certificates.json`
(8 записів, надані в архіві `lab2_data.zip`).

## Запуск: демонстрація ООП (Завдання 1)

```bash
python -m labs.lab02.main demo
```

Показує: успішний вхід, невдалий вхід, зміну email із перевіркою, права
адміністратора, завершення сесії за таймаутом, logout та записи AuditLog.

## Запуск: аналіз сертифікатів (Завдання 2)

```bash
python -m labs.lab02.main analyze \
  --certs-data labs/lab02/data/data_v10/certificates.json \
  --days-warning 30 \
  --output-report labs/lab02/data/ssl_expiry_report.json \
  --format json
```

Або звіт у CSV:

```bash
python -m labs.lab02.main analyze \
  --certs-data labs/lab02/data/data_v10/certificates.json \
  --days-warning 30 \
  --output-report labs/lab02/data/ssl_expiry_report.csv \
  --format csv
```

## Опис CLI-параметрів

| Параметр | Обов'язковий | Опис |
|---|---|---|
| `--certs-data` | так | Шлях до JSON-файлу з даними сертифікатів |
| `--days-warning` | ні (за замовчуванням `30`) | Кількість днів, за яку сертифікат вважається таким, що скоро закінчується |
| `--output-report` | ні | Шлях до файлу звіту. Якщо не вказано, звіт не зберігається на диск |
| `--format` | ні (за замовчуванням `json`) | Формат звіту: `json` або `csv` |

## Поведінка при помилках

- Якщо файл за `--certs-data` не існує — програма виводить повідомлення
  `[ERROR] Файл із сертифікатами не знайдено: ...` і завершується з кодом 1.
- Якщо файл не є коректним JSON — повідомлення про помилку розбору.
- Якщо в записі бракує обов'язкового поля (наприклад, `keyLength`) —
  програма вказує номер запису й перелік відсутніх полів.
- Якщо `--certs-data` не вказано при запуску `analyze` — `argparse`
  сам виводить довідку та код завершення 2.
